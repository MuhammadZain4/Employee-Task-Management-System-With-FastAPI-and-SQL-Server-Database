**Employee & Task Management System**

A Fast API for managing employees and their tasks, built with FastAPI and SQL Server. All database access goes through stored procedures (no inline SQL in Python), and every protected endpoint is secured with JWT authentication.

**Features**

User signup and login with bcrypt-hashed passwords
JWT access tokens, verified on every protected route
Employee management (create, read, update, delete)
Task management: employees create their own tasks, and tasks can be assigned to a specific employee
Layered architecture (routers → services → repositories) with clear responsibilities
Request and event logging to the console and to log/app.log
Tech stack

Framework	FastAPI, Uvicorn

**Layer rules**

Routers define URLs and HTTP methods, and pass data to services. No business logic here.
Services hold the logic: existence checks, role or ownership checks, and raising HTTPException.
Repositories only execute stored procedures and return the results.
Getting started
Prerequisites
Python 3.12
uv
SQL Server (Express is fine) and ODBC Driver 17 for SQL Server


1. **Install dependencies**
bash
uv sync

If you are starting from an empty environment:

bash
uv add fastapi uvicorn sqlalchemy pyodbc "passlib[bcrypt]" "bcrypt==4.0.1" "python-jose[cryptography]"

bcrypt is pinned to 4.0.1 because newer versions are incompatible with passlib 1.7.4.

2. **Configure the database connection**

Edit app/core/database.py and set your own values:

python
server = r"YOUR_SERVER\SQLEXPRESS"
database = "YOUR_DATABASE"
driver = "ODBC Driver 17 for SQL Server"

3. **Create the database objects**

In SQL Server Management Studio, select the correct database first, then run your scripts to create:

the tables (Users, Employees, Task)
the stored procedures used by the repositories (for example sp_create_user, sp_get_user_by_email, sp_create_task, sp_assign_task_to_emp)

4. **Set a real secret key**

Replace the placeholder SECRET_KEY (used for signing tokens) with a long random value, and keep it identical wherever tokens are created and verified. Do not commit it to version control.

5. **Run the server**
bash
uv run uvicorn app.main:app --reload

Open the interactive docs at http://127.0.0.1:8000/docs.

**Authentication flow**
POST /auth/signup to create an account.
POST /auth/login with email and password. The response contains an access_token.
In Swagger UI, click Authorize and paste the token.
Call any protected endpoint. Requests without a valid token receive 401 Unauthorized.

The token stores only the user's email. Services look up the matching record in the database to get the ID they need (for example emp_id), so users never supply their own identity in a request body.

**API overview**

Paths follow the project's conventions; adjust prefixes if yours differ.

Method	Path	Description	Auth
POST	/auth/signup	Register a new user	Public
POST	/auth/login	Log in and receive a JWT	Public
GET	/employee/	List employees	Required
GET	/employee/{emp_id}	Get one employee	Required
PUT	/employee/{emp_id}	Update an employee	Required
DELETE	/employee/{emp_id}	Delete an employee	Required
POST	/task/	Create a task for the logged-in employee	Required
POST	/task/assign	Assign a new task to a chosen employee	Required

**Design notes**

**IDENTITY columns** (task_id, user_id, and similar) are generated by SQL Server and are not part of the request schemas.
The logged-in user's own ID (emp_id when creating your own task) is never accepted from the client. It is resolved from the token.
IDs that the caller chooses (such as the emp_id in /task/assign) are part of the request body.
Update and delete endpoints check that the record exists first, then act.
Deleting parent rows requires removing child rows first (foreign key order), inside the stored procedure.
Route order matters: fixed paths such as /status/{status} must be declared before /{id} routes.

**Logging**

Logs are written to the console and to log/app.log in this format:

2026-09-24 15:48:59 | INFO     | app.main | Starting up ...

The log/ folder is created automatically on startup.

**Troubleshooting**

Problem	Likely cause and fix
ModuleNotFoundError: No module named 'fastapi'	You are using the wrong Python. Run with uv run uvicorn ... so the project's .venv is used.
password cannot be longer than 72 bytes	bcrypt / passlib version clash. Install bcrypt==4.0.1.
Could not find stored procedure	The procedure was created in a different database than the one in database.py.
422 on a fixed path like /status/Open	Declare the fixed route above the /{id} route.
401 invalid or expired token	Token expired (default 60 minutes), or SECRET_KEY differs between where the token is created and where it is verified. Log in again.
A value is required for bind parameter	The query's :name parameters and the dictionary keys do not match.
Security notes
Passwords are stored only as bcrypt hashes.
Keep secrets (SECRET_KEY, connection details) out of version control.
Restrict sensitive actions (delete, assign) with role checks in the services layer as your requirements grow.
